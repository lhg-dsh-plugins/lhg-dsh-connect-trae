## v2.7.0（2026-10-02）

> **新增「一键测试启用模型」**：给每个已启用的模型发一条最小消息，看哪些**真的能应答**。

### 新增

- **一键测试启用模型**（模型区新增按钮，就写这四个字后面的动作）：
  对**已启用**的每个模型发一条最小聊天请求（一句 `ping`、不带工具），逐个给出结论：

  | 结论 | 含义 |
  | --- | --- |
  | **可用** | 上游正常应答 |
  | **需要更高档位** | Trae `1005`：当前套餐不覆盖该模型 |
  | **上游不提供** | `4001` / `4011`：没有任何 SOLO 通道服务它 |
  | **被限流** | 上游限流，本次未测出 |
  | **登录凭据被拒** | 凭据失效；整轮立即停止 |
  | **本次未测出** | 超时、断连、代理、5xx——**一律不算「不可用」** |

  - **「本次未测出」是一等公民**：把限流或断连显示成「不可用」，会让你删掉一个其实能用的模型。只有上游明确的拒绝才算负面结论。
  - **这是插件里唯一消耗额度的操作**（签到改变的是账号状态、不消耗）：只在你点击时运行，没有定时也没有启动时自动跑；提示词固定为一句 `ping` 且不带工具，把花费压到最低。
  - 结果只留在当前会话里，不写入设置——「某模型上游不提供」是某一刻、某个账号的事实，持久化只会在上游改主意后继续误报。

### 说明：为什么需要它

issue #19 留下一个本地判断不了的问题：目录里有模型拿不到调用 id，而**能不能调用取决于账号档位**。本机只有免费账号，测不出付费账号的真实现状。既然无法替用户判断，就把判断交给上游——让用户一键问一次，而不是由插件猜。

本机实测（免费账号，国际版）：`gpt-5.4` / `kimi-k3` → **可用**；`gpt-6-luna` → **需要更高档位**；`gpt-6-astra` / `gpt-5.6-sol` / `glm-5.2` → **上游不提供**。

### 测试

- 全仓 395 → **413**（+18）：分类规则每个分支——尤其「不许把不确定判成不可用」；流中途抛出的拒绝带错误码时仍要分类；串行顺序与认证失败即停止；路由在方法/来源/请求体不合法时**一次调用都不发出**。
- **变异验证 3 次全部被抓**（把不确定改成负面结论 / 去掉认证即停 / 不识别 `1005`）。
